# سرور پرداخت و تحویل خودکار FMSMP

این پوشه یک سرویس Node.js است که پرداخت را از درگاه می‌گیرد و **بلافاصله رنک یا
شارد را روی سرور ماینکرفت به بازیکن می‌دهد** — بدون دخالت دستی.

> ⚠️ **این سرویس هنوز به سایت وصل نشده است.** کد نوشته و تست شده، اما تا وقتی
> شما کد پذیرنده زرین‌پال و رمز RCON را ندهید و روی یک هاست اجرا نشود، سایت
> همچنان خرید را به دیسکورد ارجاع می‌دهد.

---

## چرا سایت فعلی نمی‌تواند این کار را بکند؟

سایت روی GitHub Pages است که فقط فایل استاتیک سرو می‌کند. برای پرداخت خودکار
حتماً به یک سرور همیشه‌روشن نیاز است، چون:

1. **کد پذیرنده باید مخفی بماند** — اگر در جاوااسکریپت مرورگر باشد، هر کسی
   می‌تواند آن را ببیند.
2. **تأیید پرداخت باید سمت سرور باشد** — وگرنه کاربر می‌تواند به سایت دروغ
   بگوید که «پرداخت کردم».
3. **رمز RCON نباید در مرورگر باشد** — کسی که آن را داشته باشد، کنترل کامل
   سرور ماینکرفت را دارد.

---

## جریان کار

```
کاربر نام ماینکرفت + محصول را انتخاب می‌کند
        ↓  POST /api/pay
سرور مبلغ را از کاتالوگ خودش برمی‌دارد (نه از مرورگر)
        ↓
زرین‌پال → کاربر پرداخت می‌کند
        ↓  بازگشت به /api/callback
سرور تراکنش را verify می‌کند
        ↓
دستور از طریق RCON روی سرور ماینکرفت اجرا می‌شود
        ↓
lp user Notch parent addtemp master 30d
```

## راه‌اندازی

### ۱. پیش‌نیازها

- یک **VPS یا هاست Node.js** با IP ثابت (GitHub Pages کافی نیست)
- **کد پذیرنده زرین‌پال** — از پنل zarinpal.com
- **دسترسی RCON** به سرور ماینکرفت

### ۲. فعال‌سازی RCON

در فایل `server.properties` سرور ماینکرفت:

```properties
enable-rcon=true
rcon.port=25575
rcon.password=یک-رمز-قوی-و-تصادفی
```

سپس سرور را ری‌استارت کنید.

> 🔒 **مهم:** پورت ۲۵۵۷۵ را در فایروال فقط برای IP سرور پرداخت باز کنید.
> اگر این پورت روی اینترنت باز باشد، هر کسی می‌تواند سرورتان را کنترل کند.
> بهترین حالت این است که سرور پرداخت روی همان ماشین سرور ماینکرفت اجرا شود
> و `RCON_HOST=127.0.0.1` بماند.

### ۳. تنظیم متغیرها

```bash
cp server/.env.example server/.env
nano server/.env    # مقادیر واقعی را بگذارید
```

### ۴. تطبیق دستورات با پلاگین‌های سرور

در `server/config.mjs` بخش `CATALOG` را با پلاگین‌های واقعی خود هماهنگ کنید.
پیش‌فرض‌ها برای **LuckPerms** و **PlayerPoints** نوشته شده‌اند:

| محصول | دستور پیش‌فرض |
| --- | --- |
| رنک | `lp user {player} parent addtemp master 30d` |
| شارد | `points give {player} 100` |

اگر از پلاگین دیگری استفاده می‌کنید (مثلاً EssentialsX یا CMI)، فقط همین رشته‌ها
را عوض کنید. `{player}` خودکار با نام بازیکن جایگزین می‌شود.

**قبل از راه‌اندازی، دستور را دستی در کنسول سرور تست کنید** تا مطمئن شوید کار
می‌کند.

### ۵. اجرا

```bash
npm run server
```

ابتدا با `ZARINPAL_SANDBOX=true` تست کنید (پول واقعی جابه‌جا نمی‌شود). وقتی
مطمئن شدید، آن را `false` کنید.

برای اینکه سرویس همیشه روشن بماند:

```bash
# با pm2
npm i -g pm2
pm2 start server/index.mjs --name fmsmp-pay
pm2 save && pm2 startup
```

## تست

```bash
npm run test:payment
```

۴۱ تست اجرا می‌شود، از جمله:

- اجرای دستور روی سرور RCON شبیه‌سازی‌شده
- **دستکاری قیمت** — کاربر ۱۰۰۰ تومان می‌فرستد، سرور ۶۵۰٬۰۰۰ را اعمال می‌کند
- **تزریق دستور** — نام‌هایی مثل `user\nop hacker` رد می‌شوند
- **تحویل دوباره** — اگر کاربر لینک بازگشت را دوبار باز کند، فقط یک‌بار رنک می‌گیرد
- **سرور آفلاین** — پول ثبت می‌شود و سفارش در صف تلاش مجدد می‌ماند

## API

| مسیر | توضیح |
| --- | --- |
| `GET /api/products` | فهرست محصولات و قیمت‌ها |
| `POST /api/pay` | `{sku, player}` → لینک درگاه |
| `GET /api/callback` | بازگشت از زرین‌پال (خودکار) |
| `GET /api/order?authority=` | وضعیت سفارش |
| `GET /api/health` | بررسی سلامت سرویس |

## اتصال به درگاه‌های دیگر

کد برای زرین‌پال نوشته شده. برای **IDPay**، **NextPay** یا **زیبال** فقط دو تابع
در `server/index.mjs` تغییر می‌کند: ساخت تراکنش و تأیید آن. ساختار بقیه یکسان است.
